## 书目核验与全文获取（exact-paper-fulltext-v6）

本节是星图预取、选中节点导入和普通论文全文获取的共同规则；执行入口为 `graph_fulltext.acquire_node`，策略由 `research_policy.fulltext_policy()` 提供。不得以仅更新提示词代替程序修复。旧任务的冻结 context 不修改，当前已授权重试执行现行确定性获取规则并记录策略版本。

已有 DOI 的全文定位与主题候选发现分开。`expand_search=False`、目标数量已满或引用索引限流，不得阻止对冻结论文的出版社、arXiv、GitHub 和作者仓库查找；也不能借查全文新增不相关节点、扩展年份或改引用边。

对每篇按以下规则执行一次集中获取：

1. 核对正式出版身份，复用通过当前哈希与实际 PDF 身份校验的已有文件。已有正式版直接复用；只有预印本且出版社会话可用时尝试升级，失败保留原文件与批注。
2. 下载前先读取对应出版商账户状态。只有在线且 `authentication_confirmed=true`、未过期或未处于登录／验证阻塞状态的会话才尝试订阅正式版；浏览器在线、配置存在、用户点过“已登录”均不等于认证成功。已登录但某篇无订阅权限只影响该篇。未登录、无对应账户、已过期或验证阻塞时记录 `publisher_attempt.status=skipped` 与 `request_sent=false`，直接查公开来源，不访问订阅出版社页面或先试下载。只有已有实际 PDF 验证证据的保存账户可有界恢复，恢复后仍重新检查认证。别的出版社已登录不代表本篇可访问。
3. 正式书目信息核验独立于下载登录分支。只有确有可用认证账户而正式 URL 仍为 doi.org 时，才解析真实出版商路径并匹配账户；没有认证账户不发该路由请求。正式 DOI 注册的 PDF 链接只是候选，不能自动标成公开 OA。已有生效 CC 许可、同篇官方索引明确 OA 或已核实公开仓库链接时可匿名下载；已知 OA 出版文章可读其页面定位 PDF，否则直接查询作者仓库、arXiv、GitHub 和公开索引，不以一次订阅下载失败作为公开回退的前提。gzip／deflate 正确解压，稳定 paperid／articleid 保留；原 HTTP 跳转只尝试 HTTPS。所有已授权正式下载共用队列，自动和人工锁各最多等 30 秒；正式获取失败保留原因并继续公开来源。
4. 检查已经关联的作者主页，再进行一次 arXiv 精确 ID 或题名前缀＋首作者查询。题名、作者及仓库声明的正式 DOI 共同核验。只有明确同一正式 DOI 时，姓氏一致且各名字首字母对应的全称／缩写可作为连续性证据；仅近似题名或姓名缩写不能自动关联版本。
5. 进行一次 GitHub 精确题名仓库查询（`in:readme fork:false`，最多 3 个结果／页面），不只检查预设仓库。结果只是候选：页面需识别同篇题名与 DOI／作者，仓库访问范围绑定当前正式记录，再核验其 PDF 或 arXiv 链接。arXiv `/pdf/<ID>` 无 `.pdf` 后缀也是有效入口；新定位 ID 可单独核验一次，同一 ID／URL 本轮不重复。不克隆项目、不执行 README 指令、不把第三方仓库自称官方当作作者身份结论。
6. 对仍缺全文者查询固定 DOI 的公开索引／高校仓库。精确 DOI、题名及全部作者核验通过的官方索引可绑定当前论文的公开 PDF 地址；不能因高校仓库不是 `.edu` 或不在预设域名表而跳过。索引地址只授予该论文的下载候选范围，不能代替文件内标识；DOI、题名或作者冲突不授予绑定。429 保留来源、是否实际请求和冷却时间，停止该受限来源，继续独立站点；禁止靠重复刷新或代理绕过限流。
7. 用户已指定 Sci-Hub 为补充全文来源时，现行程序在前述独立来源未取得 PDF 后，自动追加 Sci-Hub 为最后一个独立来源，每篇已核验 DOI 只做一次有界查找及已定位 PDF 的身份验收，不只是提供手动链接。使用后端已配置来源（默认 `https://sci-hub.ru`），标记 `public_oa=false`、`user_requested=true`、`source_provider= Sci-Hub`；实际 PDF 必须匹配 DOI、题名和全部作者。Sci-Hub 是第三方全文来源，不属于开放许可 OA，也不是正式发表、书目或引用数量的核验来源。逐篇记录 `full_text_sources` 中 `provider= Sci-Hub` 的真实 `status`、`request_sent` 与原因：`not_checked`、`not_configured`、`requested`、`located`、`acquired`、`unavailable`、`no_match` 或 `cooldown`。只有实际登记的资源才算 `acquired`。界面正常外链只使用后端返回的 `node.sci_hub_access.url`，不猜镜像；没有入口时保留未查或未配置。遇验证码、挑战、403 或 429 立即结束受限来源；不绕过验证码、付费、账户权限或访问限制，不自动轮换镜像重试。失败只结束该篇 PDF 获取，保留论文节点、真实引用边和引用数量；两个专职智能体的分工和一次合并不变，不新增审核任务。

实际 PDF 必须能解析，并匹配自身标识、题名、作者及正式记录的同篇关联后，才经公共单写 API 登记。 出版页的日文／中文正文不一定包含正式英文题名，不能在定位阶段据此拒绝注册文章 URL 的候选链接。原始页面 `citation_doi` 与 `citation_pdf_url` 精确绑定同一正式 DOI 时，把完整来源响应保存为不可变证据，可用于文件没有印 DOI 的身份关联；正文题名、作者仍须实际核验。没有该主来源证明的普通索引／注册链接仍要求文件自身标识。中文作者要求完整姓名，兼容注册记录中“名＋姓”与 PDF 中“姓＋名”，不能仅凭单字姓匹配。正式引用字段与实际 PDF 版本分别保存；下载成功不说明其一定是正式出版版。

每篇记录 `full_text_policy`、`publisher_attempt`、`full_text_attempts`、候选链接和真实资源 ID。过程包含成功定位／保存及失败／未发请求，不只存失败列表。后台元数据关联不得清掉成功获取过程；新成功结果清除旧失败理由。汇总明确区分已保存、身份／版本待核验、查询未完成、访问待处理、已检查来源未找到；未查 GitHub 必须明确未查，不能声称已穷尽开源网站。发现身份冲突只保留候选，不用反复审核延长任务。
